# 存储配置化：新增配置页面 + 安装向导步骤，解除 MinIO 强绑定

## 目标

- 对象存储支持任意 S3 兼容服务（阿里云 OSS、MinIO、其他），**MinIO 仍是默认**，但不再硬绑定。
- 管理端新增「存储配置」tab（全局系统级），并复用现有表单组件在 CreateWikiModal 安装向导中新增可选「文件存储」步骤。
- 后端 S3 客户端改为**惰性初始化**：存储不可用/未配置时后端照常启动，上传时才报明确错误。
- 配置保存在 `system_settings` 表（key=`storage`），**保存过的 DB 配置优先于环境变量**；未保存时回退 env/默认值。**热切换**：客户端持有层每 60s 比对 DB，变化自动重建（api 立即生效，consumer 约 1 分钟内跟上）。

## 后端改动（backend/）

1. **config.go** — `S3Config` 扩展字段：`bucket`(默认 static-file)、`region`(默认 us-east-1)、`secure`、`public_url`；补上缺失的 `S3_ACCESS_KEY` 环境变量覆盖（现 bug：只读 ENDPOINT/SECRET_KEY）。
2. **domain** — `consts/system_setting.go` 加 `SystemSettingStorage = "storage"`；`domain/system_setting.go` 加 `StorageSetting` 结构体（provider/endpoint/access_key/secret_key/bucket/region/secure/public_url/auto_bucket）+ `StorageSettingSource` 接口（遵循 `domain/setting.go` 的 `SettingRepo` 接口先例，避免 store 层反向依赖 repo 层）。
3. **repo/pg/system_setting.go** — 新增 `GetStorageSetting`（读 key=storage）、`UpsertStorageSetting`（gorm OnConflict，现有 Update 只更不插）、`DeleteStorageSetting`（恢复默认用）。
4. **store/s3/minio.go 重构为 ClientHolder**：
   - `NewClientHolder(config, source, logger)` 构造**不联网、不返回 error** → api/consumer/migrate 启动不再因 S3 不可达失败。
   - `Get(ctx)`：RWMutex + 快照比对；初始化后每 60s 从 DB 重读配置，`reflect.DeepEqual` 发现变化则重建；DB 读失败时沿用现有客户端（不中断上传）。
   - 重建时：`minio.New`（BucketLookup 用 SDK 自动探测，MinIO 走 path-style、OSS 域名走 virtual-host）→ 桶不存在且 `auto_bucket` 开启时 MakeBucket；`SetBucketPolicy` 失败降级为 warning（兼容 OSS 预建公读桶场景），MakeBucket 失败才是硬错误。
   - 暴露 `PutObject`（内部走 Get）、`Bucket()`（返回当前配置桶名，替代写死的 `domain.Bucket`）、`PublicURL(key)`、`InternalURL(key)`。
   - **URL 收口**（消除 3 处硬编码 `http://panda-wiki-minio:9000`）：
     - `PublicURL`：配了 `public_url` 用它；否则返回相对路径 `/static-file/{key}`（经 nginx 反代，顺带修复原硬编码 URL 浏览器不可达的问题）— 用于编辑器内容。
     - `InternalURL`：`public_url` 优先，否则 `http://{endpoint}/{bucket}/{key}` — 用于 crawler 等服务端拉取（`usecase/crawler.go:55`，需给 CrawlerUsecase 注入 holder；`pkg/bot/wechat_service/wechat.go:190` 同理）。
5. **usecase/file.go** — `s3Client` 类型换为 holder；PutObject 桶名改用 `Bucket()`；`UploadFileGetUrl` 改走 `PublicURL`。
6. **新增 usecase/storage.go + handler/v1/storage.go**（admin-only，复用 `auth.Authorize + ValidateUserRole(consts.UserRoleAdmin)` 模式）：
   - `GET /api/v1/storage/setting`：当前生效配置（secret 掩码）+ 来源（default/database）+ 最近客户端错误。
   - `POST /api/v1/storage/setting`：校验 → 用新配置试建客户端（含连通性/建桶）→ 成功才 upsert + 立即重建；policy 设置失败作为 warning 返回。secret 留空 = 沿用原值。
   - `POST /api/v1/storage/test`：不保存，临时客户端做 HeadBucket + 小对象 put/get/delete 探测，返回分步结果。
   - `DELETE /api/v1/storage/setting`：删 DB 行恢复 env 默认。
   - handler 注册进 ProviderSet + `cmd/api/wire.go`。
7. **清理阻塞重构的死代码**（均无调用方，explore 已确认）：`utils/utils.go` 的 `UploadImage`、`utils/epub.go` 的 `EpubConverter`、`MinioClient.SignURL`。如你希望保留，我会改为适配新类型而不是删除。
8. 不改 `domain/llm.go:97` 的相对路径重写逻辑（与新 URL 约定天然兼容）。

2. 新增 ClientHolder 单测（fake source 验证 TTL 重建/降级路径），`go test ./store/s3 ./usecase`。

## 已知限制（如实告知）

- SecretKey 明文存 JSONB（与现有 `AutoModeAPIKey` 先例一致）；加密需引入主密钥管理，本期不做。
- 历史内容中已写入的绝对 MinIO URL 不做迁移工具。
- 切换瞬间进行中的上传可能失败一次；consumer 最长 60s 延迟感知。
