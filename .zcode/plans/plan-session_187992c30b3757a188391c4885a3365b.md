# 模型配置现代化：自研表单替换 modelkit + 模型元数据自动识别

## Context

当前模型配置表单是外部包 `@ctzhian/modelkit` 的 ModelModal：默认值（64K 上下文/8192 输出）、字段集合、"Other/自定义 provider 不给拉模型列表"等限制全烧在包里，本仓库无法修改；用户配一个 OpenAI 兼容模型要手填一堆信息（高级参数纯手填，默认值失真）。参考 ZCode（正则识别模型 id 自动填充）与 cherry-studio（精确 id + 归一化回退的模型元数据库）后，决定自研表单彻底替换 modelkit，这也是 KenFutWiki 去长亭化的必要一步。

**后端零改动**：`POST /api/v1/model/provider/supported`（拉 {base_url}/models，含非标端点特判）、`POST /api/v1/model/check`（真实请求测连通）、`POST/PUT /api/v1/model`（保存，parameters.context_window 已存 jsonb）全部现成。

## 核心复用资产（cherry-studio provider-registry，MIT）

来源：`ReferencesOpenProject/cherry-studio/packages/provider-registry/`
- `data/models.json`（950 模型：contextWindow/maxOutputTokens/inputModalities/能力）、`data/provider-models.json`（1591 条 apiModelId→modelId 别名）
- `src/utils/normalize.ts` 的日期后缀剥离（`gpt-4o-2024-08-13`/`claude-3-5-sonnet-20241022` → canonical id，不动点循环剥离）+ `registry-index.ts` 的两段式 findModel（精确 → 归一化回退）

## 改动清单（全部在 web/admin）

1. **`scripts/gen-model-catalog.mjs`（新）**：一次性脚本，从 cherry-studio 三个 data JSON 生成精简目录 `src/constant/model-catalog.json`（仅保留 id→{name, contextWindow, maxOutputTokens, supportsImage} 与别名映射，预计 200-300KB），并在文件头注明 MIT 来源，便于日后从上游同步。

2. **`src/utils/modelResolve.ts`（新，~100 行）**：移植 cherry 的归一化核心（DATE_SNAPSHOT_PATTERN 正则 + 变体后缀剥离不动点循环）+ 两段式 `resolveModelMeta(modelId)`：精确命中 → 剥日期/变体后缀重试 → 别名表查找 → 返回 null（未识别）。纯函数，附单测式注释用例（`gpt-4o-2024-08-13`、`claude-3-5-sonnet-20241022`、`qwen2.5:7b`、未识别 id）。

3. **`src/components/ModelFormModal/index.tsx`（新，自研表单）**：props 与原 ModelModal 对齐（`{open, onClose, refresh, data, model_type}`），最小化挂载点改动。交互流：
   - 基础区：provider 下拉（复用本仓 `constant/enums.tsx` 40 个 provider，按 model_type 的 chat/embedding/rerank 能力位过滤）→ base_url 自动填 `defaultBaseUrl`（urlWrite 的可编辑）→ api_key（复用 SecretTextField）→ **「获取模型列表」按钮对所有 provider 可用**（POST /provider/supported）→ 模型 id 用 Autocomplete（拉到的列表做选项，允许自由输入）
   - 模型 id 确定（onChange + 300ms 防抖）→ `resolveModelMeta` → **自动填实值**（context_window/max_output_tokens/support_image/show_name 建议）并显示「✓ 已识别：GPT-4o · 128K 上下文」提示条；未识别显示灰色「未收录，请手动填写高级参数」；一切字段可改
   - 高级参数默认折叠：context_window（128k/256k/512k/1m 快捷项）、max_output_tokens、support_image、api_header/api_version（仅 customHeader 位或 AzureOpenAI 时显示）
   - 「测试连接」→ POST /model/check 展示结果；「保存」→ 先 check 后 save（保持 modelkit 原行为），成功后 refresh()
   - 表单模式：react-hook-form + MUI（抄 pages/setting/component/CardAI.tsx 的 Controller 模式）

4. **替换两个挂载点**：
   - `src/components/System/component/ModelConfig.tsx`：L1469-1500 的 `<ModelModal>` → 新组件；删除 modelkit lazy import；`convertLocalModelToUIModel` 转换逻辑并入新组件（编辑模式回填）
   - `src/components/CreateWikiModal/steps/Step1Model.tsx`：同样替换 modelkit 引用；自动模式（AutoModelConfig）与模式切换逻辑**不动**

5. **清理**：删除 `src/services/modelService.ts`（modelkit 专用适配层，替换后无引用）；`package.json` 移除 `@ctzhian/modelkit` 依赖 + `pnpm install`；`src/api/index.tsx` 的 createModel/testModel/getModelNameList/updateModel 保留（新表单继续用）。

## 不做（明确边界）

- 不动后端任何代码；不动 DB schema（parameters jsonb 已含所需字段）
- 不动 AutoModelConfig（自动模式/百智云，功能保留）
- 不做拉取结果分组多选预览（new-api 模式）——本仓每类模型只配一个（Type uniqueIndex），单选 Autocomplete 已足够
- 不做模型列表自动定时同步（CCR 模式），后续有需要再加
